# Navigation Migration Guide

This repo moved from per-example manual navigation bindings (JSON streams + `init_oxide`) to a macro-driven, centralized navigation API.

## What Changed

- Rust init is now generated and wired into FRB initialization; do not hand-write `init_app` / `init_oxide` in example crates.
- Navigation bindings are generated by `#[oxide_generator_rs::routes]` and exposed as FRB endpoints under `crate::routes::oxide_navigation`.
- Dart navigation glue consumes a typed FRB command stream and reports the current route snapshot as a typed route payload (no JSON for route payloads).

## Rust Migration

- Remove any hand-written FRB init functions from your `api/bridge.rs` (for example `init_app()` and `init_oxide()`).
- Ensure your crate defines a `routes` module using `#[oxide_generator_rs::routes]` when `navigation-binding` is enabled.
- Re-export macro-generated endpoints for FRB discovery:
  - Add `pub mod oxide_navigation { pub use crate::routes::oxide_navigation::*; }` under your `api` module gated by `navigation-binding`.

## Dart Migration

- Replace any direct `RustLib.init()` + `initOxide()` calls with a single:
  - `await OxideStack.init();`
- Stop importing internal generated navigation files directly; import the single public entrypoint:
  - `import 'oxide.dart';`

## Removed APIs

- `initOxide()` (Dart) and `init_oxide()` / `init_app()` (Rust example bridges).
- JSON-based navigation command stream helpers and JSON route snapshot setters.
